# ミーティングノートのマイク入力

## 修正したアプリ側の不足

従来のアプリには `NSMicrophoneUsageDescription` がなく、Hardened Runtimeで署名する配布版にも `com.apple.security.device.audio-input` が付いていなかった。マイクの利用目的と音声入力のentitlementを追加し、開発用・配布用の両方の署名へ適用する。

WebKitのサイトごとの許可確認は標準動作を使う。サイトへ自動的に許可を与えたり、macOSの許可を迂回したりしない。起動時の録音、カメラ権限、システム音声収録は追加しない。

「Unable to start transcription」はNotionが複数の失敗で使う共通メッセージであり、画像だけでマイク以外の原因を除外することはできない。

## 利用時の確認

1. 修正版に更新し、入力内容を保存してアプリを再起動する。
2. Notion上で文字起こしを開始し、macOSとサイトのマイク確認を許可する。
3. 許可されない場合は、設定 → 診断 → マイク・ミーティングノートで状態を確認する。
4. 「macOSのマイク設定を開く」からWorkspace Tabsの許可を確認する。管理端末の制限はアプリから解除できない。
5. 許可変更後にページを再読み込みする。必要なら入力内容を保存してアプリを再起動する。

Web版のマイク入力を利用する。Notionデスクトップ版が持つ別アプリのシステム音声収録とは異なるため、ヘッドホンで聞いている会議相手の音声は通常マイクに入らない。マイク権限が正常でも、Notion側の利用条件・ページ権限・音声デバイス・接続状況による失敗は別途確認する。

## 開発者向けの検証

```sh
bash scripts/build.sh
python3 scripts/media_checks.py
```

利用目的と実際の署名entitlementを検査し、隔離した一時セッションでWebKitの安全なローカルページを読み込む。マイクは使用せず、生成音をAudioWorkletで処理して3秒分のフレームを確認する。出力音量はゼロ。

```sh
python3 scripts/media_checks.py --live
```

実マイクの検証はオプトイン。表示されたローカルページの「マイクのテスト開始」を押し、必要な権限を許可する。3秒分のフレームを確認したら、すべての音声トラックとAudioContextを終了する。入力音声は保存せず、外部に送信しない。ページには外部通信を禁止するCSPを設定する。

結果にはAPIの有無、サンプルレート、フレーム数、トラック終了状態のみを含める。成功はWebKitの音声入力経路の確認であり、Notionの認証・ネットワーク・サーバー側の文字起こし完了を保証するものではない。

## 2026-11-10の確認

- 変更前のインストール済みアプリでは利用目的の不足を検出した。
- 修正版の署名から音声入力entitlementを確認した。
- 通常ビルドと、Apple Development署名でHardened Runtimeを有効にした検証用アプリの両方で、16 kHz・48,000フレームのAudioWorklet処理に成功した（マイクを使わない検証）。
- インストール済みの修正版で、ユーザーの許可・開始操作後に実マイクの取得に成功。16 kHz・48,128フレーム、音声トラック1本を確認し、終了時にトラックが停止した。音声の保存・外部送信なし。
- 既存のWebKit統合テスト297項目が成功した。

配布用Developer ID証明書と公証資格情報がある環境では `scripts/release.sh` でUniversal版を署名・公証する。リリーススクリプトはアプリのバージョンを読み取り、対応するDMGを公証対象にする。
