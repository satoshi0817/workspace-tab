# 安定性調査とドラッグ追加（2026-11-06）

## 調査結果

ユーザーから報告された症状は「タブが未接続になる／ヘッダーが消える」。以下はソースと決定論的障害注入で確認した問題であり、実Notion上の個々の発生時刻をログから特定したものではない。

| 原因 | 修正 |
|---|---|
| AXRole取得の一時的エラーを閉じたウインドウと同じ扱いにしていた | プロセス終了・invalidUIElementと、cannotComplete等の応答待ちを区別して接続を保持 |
| タブ切替時のAXRaise失敗でも接続を破棄していた | 一時的失敗では接続と配置を保持 |
| 選択タブ切断時に接続済みタブへ引き継がずヘッダーが消えていた | 接続済みタブを選択し、座標の一時取得失敗時は直前のヘッダー座標を利用 |
| 移動・リサイズ直後の途中座標を全タブへ反映していた | 操作後0.8秒の抑制と、マウスを離した後0.4秒の座標安定待ち |
| タブ切替直後に返る旧フォーカスで選択を巻き戻していた | 切替後0.8秒は旧フォーカスによる巻戻しを抑制 |

実装参照：`Sources/WorkspaceTabs/Accessibility.swift:20`（接続状態）、`WorkspaceStore.swift:194`（切替失敗）、`:202`（切断）、`:328`（監視）、`:351`（切替保護）、`:362`（座標同期）、`:391`（ヘッダー選択）、`:401`（座標保持）。

付随修正：2pt未満の不要なAX座標書込みを抑制、ヘッダー／外枠の毎tickの再前面化を抑制、画面選択を最大重なり面積へ変更。追加後の遅延activateはその間のユーザー選択を上書きしない。

## ドラッグで追加

未登録の通常ウインドウのタイトルバーをドラッグし、既存グループ領域に重ねて待ち、「離すと追加」が表示されたら離す。既定1秒、設定で0.5／1／1.5／2／3秒または無効化を選べる。

上端44ptから始まる6pt超の移動を100ms毎に観測し、サイズ変更は除外。待ち時間だけでは追加せず、マウスを離したときに確定する。領域外移動、対象変更、早いreleaseでキャンセル。既登録ウインドウ、ロック中、最小化、非表示、標準全画面を除外。複数候補が重なる場所では追加先を推測しない。取り外したときの復元先はドロップ時の位置。

実装：`Sources/WorkspaceTabs/WindowDragGrouping.swift`、`Sources/WorkspaceCore/DragDwell.swift`。

## 未確認・制約

- 今回の実機fixture検証は列挙0件で失敗。過去の24項目成功は旧版の記録で、今回の成功として扱わない。以前のサイズ同期実機テスト失敗は、今回のモデルテストだけで全解決とは断定しない。
- ドラッグ→待機→releaseの実GUI全経路は未確認。使用中のCUA APIにはドラッグ途中の待機を指定する操作がなく、保持時間付きの操作を再現できなかった。
- 実Notionの長時間利用、Spaces切替、物理ディスプレイの着脱、スリープ復帰、複数アプリを合成したヘッダーの視覚検証は未完了。
- 本当にAX要素が無効化された後、同名タイトルや変更されたタイトルを安全に再接続できない場合は手動再接続が必要。
- AX監視はメインスレッド上で動くため、応答の遅いアプリでは監視やドラッグの反応が遅れる可能性が残る。
- 現在のNotionグループはロック中。ドラッグ追加・削除・手動再接続を行う場合はユーザーがロックを解除する必要がある。
