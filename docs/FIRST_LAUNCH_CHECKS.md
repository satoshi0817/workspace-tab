# 初回起動の検証と504の切り分け

## ソースから初めて使う

GitHubから新しいディレクトリにcloneして、READMEの手順でビルドします。Swift 6とmacOS 26以降のSDKを含むXcode／Command Line Tools、Python 3が必要です。RTK、Homebrew、NotionのPATは不要です。

```sh
git clone https://github.com/satoshi0817/workspace-tab.git
cd workspace-tab
bash scripts/build.sh
```

Finderで `build/Workspace Tabs.app` をApplicationsへ移動して開きます。初回ガイドの後、Notionのログイン画面でログインします。既存ユーザーが検証する場合、普段の設定・ログイン情報を削除する必要はありません。

開発用証明書や過去のビルドキャッシュを使わずに確認する場合は、次のように実行できます。

```sh
WORKSPACE_TABS_BUILD_DIR="$(mktemp -d)" WORKSPACE_TABS_SIGN_IDENTITY=- bash scripts/build.sh
```

この署名はアドホック署名です。Appleの公証や会社の端末管理ポリシーへの対応を行うコマンドではありません。

## 設定とCookieのない起動を繰り返す

```sh
"build/Workspace Tabs.app/Contents/MacOS/WorkspaceTabs" --startup-checks
```

- 毎回新しい一時設定フォルダとWebKitのプロファイルを使用し、既存セッション・Cookie・PATを読み込みません。Link Viewerの移行とNotion DB同期も実行しません。
- アプリと同じBrowserStore／BrowserEngineで `https://app.notion.com` を読み込みます。通常は `/login` へ移動します。ログイン操作やアカウント作成は行いません。
- 5回分のHTTPステータス、ログイン画面の検出結果などをJSON行で出力します。ページ本文とCookieの値は出力しません。
- 問題がなければ終了コード0、HTTPエラー・タイムアウト・初期化エラーがあれば1を返します。インターネット接続が必要です。
- 初回ガイドの見た目・操作は、この自動検証とは別にアプリ画面で確認します。

実行回数は `WORKSPACE_TABS_STARTUP_ATTEMPTS=3` などで変更できます（1〜10）。この検証はmacOS自体を再インストールするものではなく、端末のネットワーク・OS・開発ツールは実行環境を使用します。

## 504が出た場合

HTTP 504は接続先または通信経路のゲートウェイが応答待ちでタイムアウトしたことを表します。ビルドに成功したことと、接続先の応答が正常であることは別です。コードとエラー画面だけから、Notion・社内プロキシ・VPNなどのどこが返したかを断定することはできません。

アプリはメインページのHTTP 5xxを読み込み失敗として表示し、元のURLを手動で再試行できます。自動で再読み込みを繰り返したり、作成操作やフォーム送信を再送したりはしません。画像など一部リソースだけの失敗は、表示可能なページ全体をエラーに置き換えません。

報告時は、表示されたHTTPコード、画面のURL、macOSのバージョン、ビルドコマンドが分かると切り分けやすくなります。Cookie、PAT、認証トークンを含むURLは共有しないでください。

## 2026-11-09の確認結果

検証端末はApple SiliconのMacです。Swift 6.3、macOS SDK 26.4を含むCommand Line Toolsで確認しました。以下はこの端末・この通信環境での結果です。

| 対象 | 確認内容 | 結果 |
| --- | --- | --- |
| GitHubのmain（d567532） | 新規clone、新しいビルドディレクトリ、アドホック署名 | クリーンビルド成功、設定なしのQAコピーでNotionログイン画面を表示 |
| 修正後のソース一式 | 別の空ディレクトリ、新しいビルドディレクトリ、アドホック署名 | 2回目のクリーンビルド成功 |
| 修正後の起動 | 検証用識別子、5回の別プロセス、毎回新しい設定とWebKitプロファイル | 5回ともCookie 0件から開始し、HTTP 200・ログイン画面を検出 |
| 初回ガイド | 実機で3ステップを完了 | ログイン画面まで正常に表示 |
| 既存の配布DMG v0.2.0 | GitHubから実ファイルを取得し、SHA-256・元アプリの署名を検証。設定隔離のため識別子を変えたQAコピーを3回起動 | 3回ともログイン画面へ到達。1回は実画面の入力欄まで確認 |
| HTTPエラー | ローカルサーバーでメインページの504／503、一度504になって再試行で200、画像のみ503を再現 | 案内の保持、元URLへの手動再試行、無限リロードの防止、正常ページの維持を確認 |

実際のNotionへのアクセスで報告と同じ504は再現していません。報告されたURL・macOS・ネットワーク条件が不明のため、その504の発生元は特定できていません。今回修正したのは、HTTP 5xxを通常の読み込み成功として扱うことと、キャンセル後のWebKit通知がHTTPエラーの説明を上書きすることです。

上記の既存DMGの確認は差し替え前のビルド3が対象です。その後、v0.2.0のDMGをHTTPエラー処理とグレーの初期色を含むビルド4へ更新しました。更新後はGitHubから再ダウンロードし、チェックサム・署名・同梱実行ファイルを照合しています。Gatekeeperの初回許可、会社の端末管理下、別バージョンのmacOSでの起動をすべて保証する検証ではありません。

追加監査とv0.2.1（ビルド5）の修正・検証結果は[起動・安定性の再監査](STARTUP_STABILITY_AUDIT.md)を参照してください。
